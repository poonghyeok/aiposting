안녕하세요! Azure Data Explorer(Kusto)를 사용하다 보면 여러 테이블의 데이터를 결합해야 하는 상황이 자주 발생합니다. Kusto Query Language(KQL)에서 제공하는 `join` 연산자는 SQL의 `JOIN`과 비슷하면서도 몇 가지 독특한 특징을 가지고 있는데요. 오늘은 Kusto에서 지원하는 대표적인 `join` 종류와 각각의 적절한 사용 케이스, 그리고 자세한 예시 코드를 함께 알아보겠습니다.

---

### 1. Inner Join (내부 조인): 교집합 찾기

`kind=inner`는 두 테이블 모두에 공통으로 존재하는 키 값을 가진 행만 결과로 반환합니다. 양쪽 테이블에 모두 일치하는 데이터가 있을 때만 유효합니다.

*   **적절한 사용 케이스:** 사용자 ID를 기준으로 로그인 로그와 사용자 프로필 정보가 모두 존재하는 활성 사용자의 데이터를 분석할 때 유용합니다.
*   **예시 코드:**

```kusto
let Users = datatable(UserId:string, UserName:string) [
    "U1", "김철수",
    "U2", "이영희",
    "U3", "박민수"
];
let Logins = datatable(UserId:string, LoginTime:datetime) [
    "U1", datetime(2023-10-01 10:00:00),
    "U2", datetime(2023-10-01 11:00:00),
    "U4", datetime(2023-10-01 12:00:00)
];
Users
| join kind=inner (Logins) on UserId
```

---

### 2. Left Outer Join (왼쪽 외부 조인): 기준 테이블 중심

`kind=leftouter`는 왼쪽 테이블의 모든 행을 유지하면서, 오른쪽 테이블에서 일치하는 행을 가져옵니다. 일치하는 데이터가 없다면 오른쪽 테이블의 컬럼 값은 빈 값(null)으로 채워집니다.

*   **적절한 사용 케이스:** 모든 주문 내역(왼쪽)을 조회하면서, 만약 존재하는 경우에 한해 배송 정보(오른쪽)를 함께 확인하고 싶을 때 사용합니다.
*   **예시 코드:**

```kusto
let Orders = datatable(OrderId:string, Item:string) [
    "O1", "노트북",
    "O2", "마우스",
    "O3", "키보드"
];
let Deliveries = datatable(OrderId:string, Status:string) [
    "O1", "배송완료",
    "O2", "배송중"
];
Orders
| join kind=leftouter (Deliveries) on OrderId
```

---

### 3. Left Semi Join (왼쪽 세미 조인): 존재 여부 확인

`kind=leftsemi`는 오른쪽 테이블에 일치하는 행이 존재하는 왼쪽 테이블의 행들만 반환합니다. 오른쪽 테이블의 데이터는 결과에 포함되지 않고 필터링 목적으로만 사용됩니다.

*   **적절한 사용 케이스:** 특정 에러 로그 목록(오른쪽)에 해당하는 사용자 ID만 추출하여, 전체 사용자 접속 기록(왼쪽) 중 에러를 경험한 사용자들의 데이터를 필터링할 때 적합합니다.
*   **예시 코드:**

```kusto
let AllUsers = datatable(UserId:string, Activity:string) [
    "U1", "조회",
    "U2", "구매",
    "U3", "장바구니"
];
let SuspiciousUsers = datatable(UserId:string) [
    "U2",
    "U3"
];
AllUsers
| join kind=leftsemi (SuspiciousUsers) on UserId
```

### 결론

지금까지 Azure Kusto에서 자주 쓰이는 `inner`, `leftouter`, `leftsemi` 조인의 종류와 사용 케이스를 예시 코드와 함께 살펴보았습니다. KQL의 `join`은 데이터의 구조와 분석 목적에 맞추어 `kind` 옵션을 적절히 선택하는 것이 성능과 결과 정확도 측면에서 매우 중요합니다. 공식 문서나 실제 운영 환경의 데이터 규모에 따라 동작 방식이 미세하게 달라질 수 있으므로, 실제 적용 전 작은 데이터셋으로 테스트해 보시는 것을 권장합니다.
